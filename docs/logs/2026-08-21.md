## Phase 2 T2.3 comparison gate

- Added the standalone, offline-only `toolCompatibilityCompare` task. It accepts one saved
  untreated run and one saved prompted run directly under `build/tool-compatibility/`; it starts
  neither Spring nor a model provider.
- The gate verifies both condition directories and their deterministic summaries before comparing
  them. It requires one clean shared Git commit, matching Spring Boot/Spring AI versions, model
  identity and digest, all non-prompt protocol and semantic-oracle identities, and the identical
  locked paired-execution schedule.
- It treats `globalPairSequence` and `conditionExecutionPosition` as schedule-derived values:
  their expected untreated/prompted differences are accepted only when each row matches the shared
  schedule for its case and repetition. Missing, equal, swapped, or inconsistent positions fail
  before any later report can render deltas.
- Observed provider-turn, tool-call, callback, output, usage, latency, and classified diagnostic
  differences remain intentionally uninterpreted here for the later deterministic-report slice.
- No Ollama request, model pull, provider call, live evidence allocation, or semantic prompt
  decision was performed.
