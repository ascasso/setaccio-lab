## Deterministic evaluator benchmark

### Summary
- Added the local-only `POST /api/lab/evaluations` endpoint for deterministic public fixture evaluation runs.
- Added Spring AI `Evaluator` contract coverage through the `fixture` / `term-containment-v1` evaluator, which produces explicit pass/fail verdicts, scores, feedback, and metadata without calling a model provider.
- Added evaluation request, fixture, row, and result models that retain the user text, optional fixture context, response text, evaluator identity, and execution failure details.
- Reused `LabResultWriter` to persist `*-evaluation.json` results under the configured lab output directory.
- Added service and controller tests for default fixtures, selected fixtures, deterministic scores, persisted results, and unknown fixture validation.
- Updated the README, environment guide, test plan, and changelog to distinguish deterministic contract coverage from future opt-in AI-judged evaluation.

## Tool Search comparison benchmark

### Summary
- Added `advisorMode: "compare"` to `POST /api/lab/tools` for sequential standard `ToolCallingAdvisor` and Tool Search Advisor benchmark runs using the same models, prompts, and deterministic selected tools.
- Kept Tool Search comparison disabled unless `SETACCIO_LAB_TOOL_SEARCH_ENABLED=true`; direct `advisorMode: "tool_search"` requests remain rejected so Tool Search output always has its standard baseline.
- Implemented the in-memory Spring AI regex index as the only executable index in this slice. Unsupported index values are rejected rather than implying Lucene or vector coverage.
- Added a comparison result envelope and one `*-tool-calling-comparison.json` output per request. It retains both nested result sets and does not claim an aggregate winner.
- Added mocked service and controller coverage for the complete Tool Search sequence, result persistence, configuration guards, and the Spring AI 2.0 generated Tool Search callback schema.
- Updated public benchmark, environment, and test-plan documentation to distinguish the executable regex comparison from later index and MCP work.

- Manual local-profile smoke run with Tool Search explicitly enabled using `gemma4:e2b` and one arithmetic prompt: `POST /api/lab/tools` with `advisorMode: "compare"` returned HTTP 200 and a `tool-calling-comparison` result envelope.
