## Sequential vision matrix and offline analyzer

- Added a dedicated `visionMatrix` source set and opt-in Gradle task that:
  - requires the fixed ignored `local/vision-corpus` directory;
  - requires explicit unique Ollama model tags;
  - requires one declared token policy, either `none` or a fixed limit;
  - requires a new dated direct child of `build/vision-matrix/`;
  - forces Ollama's pull strategy to `never`;
  - verifies every requested normalized tag against Ollama's installed-model
    list and fails before output allocation when any tag is missing;
  - runs model/case/repetition rows strictly sequentially;
  - fixes temperature at `0.0`, repetitions at two, and effective seeds at
    `42` and `43`.
- Added a vision-specific corpus reader that rejects:
  - unsupported versions and unknown fields;
  - blank, duplicate, or unsafe case IDs;
  - paths that are not `images/<caseId>.<supported-extension>`;
  - missing, empty, symbolic-link, or path-escaping inputs;
  - mismatched MIME bytes or BLAKE3 digests;
  - blank reference/expectation/limitation metadata;
  - incomplete sensitive-content review.
- Added suite-specific vision matrix results that retain safe case IDs, MIME
  types, BLAKE3 input identities, prompt identity, invocation settings, token
  metadata, latency, outputs, structural checks, and classified errors without
  copying local paths, original filenames, reference observations, expected
  concepts, unsupported-detail notes, or raw provider exception messages.
- Added shared v1 evidence output with:
  - immutable `vision-matrix-results.json`;
  - `manifest.json` with Git/framework provenance, locked protocol settings,
    and SHA-256 artifact integrity;
  - deterministic `SUMMARY.md`.
- Added `visionMatrixVerify` and `visionMatrixReanalyze` for saved v1 runs.
  Both operate without Spring application startup, corpus access, Ollama, or a
  remote provider. Reanalysis rewrites only the deterministic summary and
  refuses to proceed when immutable inputs fail validation.
- Kept invocation success, structural completion, expected-observation review,
  unsupported-detail review, repetition diagnostics, token availability,
  successful-invocation latency, and infrastructure failures separate.
  Semantic review fields remain `not performed` until human analysis.
- Reported median and observed latency range for successful invocations rather
  than percentiles from two repetitions.
