# 2026-07-12

## First controlled local Tool Search model matrix

### Protocol

- Code baseline: `b5922d9` (`Add expectation-aware Tool Search benchmarks`).
- Spring AI: `2.0.0`; Tool Search index: `regex`; configured maximum search results: `5`.
- Models: `gemma4:e2b`, `granite4.1:3b`, and `qwen3.5:0.8b`.
- The third model was selected from the existing local Ollama inventory and passed a one-request direct tool-calling smoke check. No model was pulled or downloaded.
- Cases: `arithmetic-add`, `catalog-lookup`, `catalog-multi-step`, `no-applicable-domain-tool`, and `deterministic-tool-failure`.
- Repetitions: `2`; temperatures: `0.0`; effective seeds: `42` and `43`; comparison order: `alternate`.
- No `maxTokens` limit was supplied; model defaults were retained because a common generation ceiling was not needed for this bounded run.
- `advisorMode` was `compare` only. The 60 rows are 3 models × 5 cases × 2 repetitions × 2 advisors, with paired sequential execution.
- Tool Search was enabled only for the local-profile run. Raw output is ignored under `build/lab-results/`.

### Post-run correction

The temporary request transcribed the deterministic failure response marker as `DETERMINISTIC_TOOL_FAILURE`, while the Java case source and fixture use `fixture-tool-failure`. The raw rows consistently captured `fixture-tool-failure` whenever the callback executed, so the recorded `tool_response_contains` failures for those executions are request-construction errors rather than model failures. The corrected contract counts below re-evaluate only that assertion against the immutable raw rows; all other assertions and observations are unchanged. The ignored JSON retains the original request and recorded verdicts as the audit source.

After correcting the transcribed marker, the only standard failure was the catalog lookup output for `gemma4:e2b`. Tool Search added these patterns:

- `gemma4:e2b`: no discovery response for arithmetic, multi-step, and no-applicable-tool; discovery and execution checks consequently failed. Tool Search catalog lookup and deterministic failure both passed. The `Policy FAQ` output miss occurred only in the standard catalog rows.
- `granite4.1:3b`: no discovery response for arithmetic, no-applicable-tool, and deterministic failure. Multi-step discovery/execution did not satisfy both required callbacks and its output missed the required fixture term. Catalog lookup passed.
- `qwen3.5:0.8b`: arithmetic, no-applicable-tool, and deterministic failure passed. Catalog lookup discovered and executed the lookup callback but missed `Policy FAQ`; multi-step discovered and executed the list callback but did not execute the required lookup callback.

Observed Tool Search traces were semantically useful but not uniformly sufficient. Successful examples included queries such as `addition calculator or math tool`, `fixture-policy-faq catalog`, and `deterministic failure fixture`; discovered sets often included distractors. The multi-step failure for `qwen3.5:0.8b` is specifically discovery/execution incompleteness, not invocation failure. The no-applicable-tool passes for `qwen3.5:0.8b` show that discovery can complete while correctly producing no domain callback.

### Next experiment

The evidence supports a small diagnostic follow-up, not a provider or index expansion: use richer trace inspection around failed Tool Search discovery and multi-step continuation. Any subsequent controlled matrix should generate its temporary request directly from a source review or mechanically validate every prompt and expectation against `ToolBenchmarkCases` before execution. It should preserve the same models, seeds, temperature, paired order, and offline/default-test boundaries so changes in discovery and execution can be attributed cleanly.
