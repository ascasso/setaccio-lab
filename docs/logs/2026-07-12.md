# 2026-07-12

## First controlled local Tool Search model matrix

### Protocol

- Code baseline: `b5922d9` (`Add expectation-aware Tool Search benchmarks`).
- Spring AI: `2.0.0`; Tool Search index: `regex`; configured maximum search results: `5`.
- Models: `gemma4:e2b`, `granite4.1:3b`, and `qwen3.5:0.8b`.
- The third model was selected from the existing local Ollama inventory and passed a one-request direct tool-calling smoke check. No model was pulled or downloaded.
- Cases: `arithmetic-add`, `catalog-lookup`, `catalog-multi-step`, `no-applicable-domain-tool`, and `deterministic-tool-failure`.
- Repetitions: `2`; temperatures: `0.0`; effective seeds: `42` and `43`; comparison order: `alternate`.
- No `maxTokens` limit was supplied; model defaults were retained because a common generation ceiling was not needed for this bounded run.
- `advisorMode` was `compare` only. The 60 rows are 3 models × 5 cases × 2 repetitions × 2 advisors, with paired sequential execution.
- Tool Search was enabled only for the local-profile run. Raw output is ignored under `build/lab-results/`.

### Results

Every invocation completed successfully (`10/10` rows per model and advisor). Invocation success therefore exceeded contract success in every group:

| Model | Advisor | Contract passed | Tokens in | Tokens out |
| --- | --- | ---: | ---: | ---: |
| `gemma4:e2b` | standard | 6/10 | 10,848 | 4,036 |
| `gemma4:e2b` | Tool Search | 2/10 | 8,168 | 3,821 |
| `granite4.1:3b` | standard | 8/10 | 12,024 | 774 |
| `granite4.1:3b` | Tool Search | 2/10 | 7,364 | 739 |
| `qwen3.5:0.8b` | standard | 8/10 | 14,628 | 2,360 |
| `qwen3.5:0.8b` | Tool Search | 4/10 | 22,959 | 4,149 |

The standard and Tool Search results are not a single winner score. They expose different failure surfaces: invocation completion, discovery completion, required-tool discovery, required-tool execution, output terms, and tool-response terms.

Per case, each cell is contract-passed rows out of two repetitions (`standard / Tool Search`):

| Model | arithmetic | catalog lookup | catalog multi-step | no applicable tool | deterministic failure |
| --- | ---: | ---: | ---: | ---: | ---: |
| `gemma4:e2b` | 2/0 | 0/2 | 2/0 | 2/0 | 0/0 |
| `granite4.1:3b` | 2/0 | 2/2 | 2/0 | 2/0 | 0/0 |
| `qwen3.5:0.8b` | 2/2 | 2/0 | 2/0 | 2/2 | 0/0 |

Standard failures were concentrated in the catalog lookup output for `gemma4:e2b` and the deterministic failure response-term check for all three models. Tool Search added these patterns:

- `gemma4:e2b`: no discovery response for arithmetic, multi-step, and no-applicable-tool; discovery and execution checks consequently failed. It did discover and execute the catalog lookup successfully, but its final output missed `Policy FAQ`. Its failure fixture executed, but the required response marker was absent.
- `granite4.1:3b`: no discovery response for arithmetic and no-applicable-tool; multi-step discovery/execution did not satisfy both required callbacks and its output missed the required fixture term. Catalog lookup passed. The failure fixture also lacked the required response marker.
- `qwen3.5:0.8b`: arithmetic and no-applicable-tool passed. Catalog lookup discovered/executed the lookup callback but missed `Policy FAQ`; multi-step discovered/listed the catalog but did not execute the required lookup callback. The failure fixture executed but lacked the required response marker.

Observed Tool Search traces were semantically useful but not uniformly sufficient. Successful examples included queries such as `addition calculator or math tool`, `fixture-policy-faq catalog`, and `deterministic failure fixture`; discovered sets often included distractors. The multi-step failure for `qwen3.5:0.8b` is specifically discovery/execution incompleteness, not invocation failure. The no-applicable-tool passes for `qwen3.5:0.8b` show that discovery can complete while correctly producing no domain callback.

### Next experiment

The evidence supports a small diagnostic follow-up, not a provider or index expansion: repeat the same five cases with richer trace inspection around failed Tool Search discovery and multi-step continuation, then test whether the deterministic failure expectation matches the actual public fixture response wording. A subsequent controlled matrix should preserve the same models, seeds, temperature, paired order, and offline/default-test boundaries so changes in discovery and execution can be attributed cleanly.
