## Small-Model Tool-Calling Compatibility Plan review-finding revisions

Addressed three PR #38 review findings against
[SmallModelToolCallingCompatibilityPlan.md](../SmallModelToolCallingCompatibilityPlan.md).
Documentation only; no implementation, live model call, or Docker use
occurred.

- Corrected the Phase 0 slice T0.1 filename reference from the stale
  `docs/SMALL-MODEL-TOOL-CALLING-PLAN.md` to the actual tracked path
  `docs/SmallModelToolCallingCompatibilityPlan.md`, and reworded the
  instruction to "Track this plan as" rather than instructing the
  implementer to create a file that already exists. Confirmed no other
  stale filename references exist in the repository.
- Strengthened Appendix A4/A5 and the Phase 1 result-row shape and analysis
  counts so that ordinary Spring AI callback DTO coercion (for example,
  binding `{"count":"5"}` into `int count`) cannot be mistaken for evidence
  that the model emitted schema-valid tool-call arguments. The plan now
  requires preserving the raw tool-call argument JSON before callback
  binding, validating it against the tool's declared JSON Schema, and
  recording `rawArgumentJsonValid`, `rawArgumentSchemaValid`,
  `callbackBindingSucceeded`, `callbackExecuted`, and `callbackSucceeded` as
  separate dimensions. Added the `RAW_ARGUMENT_SCHEMA_MISMATCH` diagnostic,
  distinct from callback-failure categories, without requiring a custom
  lenient/strict `ObjectMapper` or any change to existing framework
  coercion behavior.
- Locked Phase 4's fresh 64-token and 256-token arms to the same clean Git
  commit. The comparison gate now requires equality for Git commit,
  dirty-worktree state, Spring Boot version, Spring AI version, execution
  engine, judge model digest, prompt identity, fixture catalog identity,
  human-review identity, row order, temperature, seeds, timeout, and attempt
  policy, permitting differences only in maximum output tokens, run ID,
  generated timestamp, output-directory identity, and observed invocation
  outcomes. Added an explicit stop-and-restart rule if the worktree becomes
  dirty or the commit changes between arms, and clarified that the historic
  A5 run remains contextual evidence only, not one arm of the causal
  comparison.

Propagated the Phase 4 same-commit gate into
[docs/DEFERRED-WORK.md](../DEFERRED-WORK.md) and [AGENTS.md](../../AGENTS.md)
where they describe the required gate before that experiment begins.
`docs/TEST-PLAN.md` and `docs/ENVIRONMENT.md` describe the already-completed
A5 run in the past tense and did not require changes.
