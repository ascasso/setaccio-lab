## Slice A2: dedicated recording judge boundary

- Re-checked the pinned Spring AI `2.0.0` `FactCheckingEvaluator`,
  `ChatClient.Builder`, `OllamaChatModel`, Ollama options, and Spring retry
  contracts before implementation. The upstream evaluator still returns only
  a supported-claim boolean with empty feedback/metadata and builds one chat
  request from `{document}` and `{claim}`.
- Added `LocalFactCheckJudgeSettings` so every future judge call must state the
  model, temperature, seed, token limit, timeout, and exactly-one-attempt
  policy. No application or environment default can select the judge.
- Added a dedicated Ollama judge factory that accepts only an explicit loopback
  URL, applies connection/read timeout, propagates complete Ollama generation
  options, uses pull strategy `never`, and configures Spring AI with zero
  retries after the initial call.
- Added a request-scoped recording `ChatModel` around Spring AI's unchanged
  `FactCheckingEvaluator`. It captures the exact raw output, response ID/model
  and provider attributes, token usage when available, latency, and attempt
  count before the evaluator reduces the answer to a boolean.
- Added a result contract that keeps provider invocation success, Spring's
  supported-claim boolean, normalized judge verdict, human-confirmed expected
  label agreement, and diagnostic category separate. Only trimmed,
  case-insensitive exact `yes` and `no` are valid verdicts; empty and malformed
  output are not converted to `no`.
- Added explicit unavailable-model, timeout, provider-failure, empty-response,
  malformed-verdict, and expectation-mismatch categories. The unavailable
  signal is typed for the later installed-model preflight slice.
- Kept A2 provider-free in the default lifecycle. It adds no Spring judge bean,
  endpoint, Gradle runner, environment variable, evidence writer, provider
  call, model pull, credential, dependency, Docker behavior, or Testcontainers
  behavior. A3 evidence and A4 live-run work remain pending.

## Slice A3: offline evaluation evidence lifecycle

- Added a dedicated `localEvaluation` source set for the suite-specific
  protocol, analyzer, evidence writer, deterministic report, and offline
  runner. No live `localEvaluation` task was added.
- Locked protocol version `1` to twelve sequential rows: three public document
  pairs with supported-then-unsupported order for repetition one/seed `42`,
  then unsupported-then-supported order for repetition two/seed `43`.
  Temperature remains `0.0`; token limit and timeout must be explicit and
  positive; every row must record exactly one attempt and pull strategy
  `never`. Because order, repetition, and seed change together, the report
  explicitly makes no order-effect claim.
- Added BLAKE3 document and claim identities without copying full fixture text
  into raw evidence. The raw protocol also binds the prompt, fixture catalog,
  actual-human review, requested/normalized judge name, full model digest,
  generation settings, row schedule, raw response, response metadata,
  available usage, latency, evaluator boolean, normalized verdict,
  expectation agreement, and classified outcome.
- Added `local-evaluation-results.json`, the shared v1 `manifest.json` with
  SHA-256 artifact integrity and Git/framework provenance, and deterministic
  `SUMMARY.md`. The summary reports supported and unsupported agreement
  separately, repetition consistency, always-yes/always-no tendency,
  empty/malformed output, token availability, latency range/median, attempts,
  timeouts, and infrastructure failures.
- Added standalone `localEvaluationVerify` and `localEvaluationReanalyze`
  tasks. They accept only a saved direct child of ignored
  `build/evaluation-matrix/`, do not start Spring, and do not inspect an
  endpoint or contact Ollama. Reanalysis replaces only `SUMMARY.md` after raw
  evidence and its manifest descriptor pass inspection.
- Canonicalized unavailable/timeout/provider errors before persistence and
  reject response metadata that contains endpoint, credential, environment,
  host, or user-path data while retaining exact raw judge output.
- Added offline coverage for exact schedule and metrics, identity drift,
  row-order/count drift, invalid attempts, unclassified/incoherent outcomes,
  partial usage, sensitive metadata, raw and summary tampering, missing/extra
  artifacts, unsafe paths, deterministic summary repair, non-overwrite
  behavior, and end-to-end offline runner invocation.
