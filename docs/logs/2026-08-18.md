## T1.4 canonical tool-compatibility result row

- Added the suite-specific canonical result, row, provider-turn, tool-call,
  tool-response, usage, failure, and diagnostic types only after the committed
  T1.3 observability proof.
- Preserved provider turns, raw tool calls, and callback responses as separate
  ordered evidence. Lifecycle stages use explicit `NOT_REACHED`,
  `UNOBSERVABLE`, `SUCCEEDED`, and `FAILED` states where nullable booleans
  would conflate binding, execution, and callback-result outcomes.
- Added the bounded T1.4 row analyzer that converts the temporary T1.3 trace,
  revalidates raw JSON/schema and exact semantic-oracle observations, enforces
  turn/call/response linkage, and derives exact call sequence, expected
  arguments, canonical assertions, final completion, output-limit state, and
  aggregate usage without flattening multi-step calls.
- Added complete logical-row wall-clock latency to the existing invocation
  trace so canonical rows retain the observed deadline-bounded duration rather
  than inventing it from provider-turn latency.
- The canonical result locks protocol, provider, execution, no-pull, model,
  untreated system-prompt, oracle, ordered case, ordered tool, tool-definition,
  schedule, and full 16-row identities. It contains no endpoint, host,
  credential, or absolute-path field.
- Canonical constructors reject contradictory aggregates, malformed lifecycle
  combinations, broken provider-turn/tool-call/tool-response links, unsafe
  timeout traces, incomplete results, and drift from the current locked
  protocol. Failure messages are reduced to stable public-safe categories;
  raw provider exception messages are not copied into canonical rows.
- Reused the existing `ToolBenchmarkAssertion` type because its named
  check/target/pass/detail semantics match the canonical case assertions. No
  singular row-level raw-argument, callback-response, finish-reason, or
  arbitrary assistant-output shortcut was added.
- Added provider-free strict JSON round-trip and unknown-field tests, aggregate
  tamper tests, turn/call/response linkage tests, numeric-scale semantic-oracle
  coverage, callback binding-versus-invocation lifecycle coverage, and the
  complete 16-row result contract.

## T1.6 deterministic tool-compatibility analysis

- Added a provider-free analyzer that revalidates the complete canonical result
  against the locked protocol before producing metrics. Result identity drift,
  row projection drift, unclassified failed contracts, unsupported schema
  states, and report/result mismatches remain experimental-integrity failures;
  they are never counted as ordinary compatibility outcomes.
- Added separate immutable summaries for invocation, tool selection, raw and
  semantic arguments, callback lifecycle, completion, observable
  reasoning-style output, usage, and latency. No combined score or model
  ordering exists.
- Selection analysis counts expected call occurrences and distinguishes
  missing, additional, reordered, and duplicate calls. It separately records
  forbidden selections, unnecessary calls, valid abstentions, and exact
  ordered-call agreement.
- Argument analysis retains valid, invalid, unobservable, and not-reached
  states per call. Framework-bound calls whose raw schema or semantic oracle
  failed remain explicit coercion findings rather than becoming schema-valid.
- Execution analysis keeps binding, execution, and callback-result states
  separate and recognizes the locked deterministic callback failure only when
  its exact call, arguments, failed response, and response assertion survive.
- Added one exhaustive primary-diagnostic taxonomy and precedence. Timeout and
  provider failures precede malformed JSON; malformed JSON and specific raw
  schema issues precede callback findings; callback findings precede call
  sequence and semantic-argument mismatches; completion categories come last.
  A correctly retained expected callback failure does not mask an unrelated
  contract defect. A failed contract without one supported category is an
  integrity failure.
- Passing rows may retain `VISIBLE_REASONING_TEXT`, but failed rows receive
  their primary failure category while the independent reasoning booleans
  remain available. `<think>` tags and other locked markers are now counted
  separately without making claims about private reasoning.
- Added ordered per-turn token evidence, deterministic row aggregates, and
  successful-contract latency median plus observed minimum/maximum. With two
  repetitions, no percentile statistic is produced. Installed-model absence
  remains a preflight integrity failure, so a valid canonical result records
  zero unavailable models.
- Added a deterministic Markdown report that covers every required dimension,
  per-turn usage, per-row usage, category counts, and one primary category for
  every failed contract. The renderer rejects analysis from different raw
  rows.
- Added table-driven fixtures for every category and every precedence edge,
  complete 16-row counts, missing/additional/reordered/duplicate selection,
  forbidden use and abstention, callback coercion, expected callback failure,
  empty final output, provider-turn failure location, complete/partial/absent
  usage, output limits, exact two-value median/range, and report exclusions.

## T1.7 tool-compatibility offline evidence lifecycle

- Added the exact four Phase 1 Gradle task contracts:
  `toolCompatibilityTest`, `toolCompatibilityMatrix`,
  `toolCompatibilityVerify`, and `toolCompatibilityReanalyze`.
  The live matrix task requires the explicit loopback URL, locked model tag,
  `512`-token per-turn limit, `PT2M` whole-row deadline, and one new dated
  output directory; none has a default or environment fallback.
- Added configuration-cache-safe task wrappers with explicit working-directory
  properties. The new wrappers do not call `Task.project` during task actions,
  and verify/reanalyze execute a dedicated provider-free main class.
- Added strict preflight that validates all local protocol identities, callback
  schemas, safe direct-child output containment, date and path syntax,
  symbolic-link absence, non-overwrite allocation, installed model identity,
  and full digest before any evidence directory is created.
- Added the sequential live runner and executor over the existing standard
  `ToolCallingAdvisor` invocation boundary. One boundary instance spans all 16
  rows so an unconfirmed stopped timeout prevents the next row; no retry,
  replacement, pull, fallback, or Spring application context was introduced.
- Added the exact ignored three-file layout:
  `tool-compatibility-results.json`, `manifest.json`, and `SUMMARY.md`. The
  shared-v1 manifest records relative artifact paths, SHA-256 and size,
  framework versions, pre-execution Git state, full model/protocol/prompt/
  oracle/tool-definition identities, and the complete ordered schedule.
- Added strict standalone offline verification and deterministic reanalysis.
  They reject unsafe run roots, path traversal, symbolic links, missing, empty,
  extra, size- or hash-drifted artifacts, manifest envelope/settings drift,
  strict raw-result parse or analysis failure, and summary drift. Reanalysis
  rewrites only a missing or drifted summary after all immutable inputs pass.
- Extended the deterministic summary with relative raw-artifact identity and
  captured Git provenance while preserving the separate T1.6 dimensions and
  interpretation boundary. No hostname, provider endpoint, credential,
  absolute output path, aggregate score, rank, percentile, or semantic quality
  judgment is written.
- Added provider-free lifecycle fixtures for fresh writes, exact layout,
  overwrite rejection, outside-root and invalid-date paths, parent/output
  symlinks, raw tampering, missing/empty/extra artifacts, manifest path and
  settings drift, byte-identical summary repair, strict live argument parsing,
  and standalone offline runner operation.
